How to repeat these checks

Every app got the same checks, in this order, on Standard, free trial. Anyone with a site on that plan can repeat them. How we run every comparison

  1. E1

    A new page under a restricted parent gets its edit restriction

    A page is created under a parent whose editing is restricted, and after a short wait its own edit restriction is read. If it comes only after the app's own button is pressed, the result is partial.

  2. E2

    Pages already under the parent get it

    The parent's editing is restricted after its pages exist, and the edit restrictions of the pages under it are read. If they come only after the app's own button is pressed, the result is partial.

  3. E3

    A page two levels down gets it too

    The edit restriction of a page under a page under the parent is read at the same moment as its own parent page's, and must be there whenever that page has it, so a weakness one level up is not counted twice. If that page never gets it, this check cannot be judged.

  4. E4

    A page moved under the parent gets it

    A page from elsewhere in the space is moved under the restricted parent, and its edit restriction is read. If it comes only after the app's own button is pressed, the result is partial.

  5. E5

    Lifting the parent's restriction lifts it below

    The parent's restriction is removed, and the pages that had it only from the parent must have none left. If this happens only after the app's own button is pressed, the result is partial.

  6. E6

    A page's own stricter restriction is kept

    One page under the parent allows only the lab's account to edit. After the parent is restricted for the lab's group and account, and again after that restriction is lifted, the page must still allow only the account. An app's own account, which an app needs on a restriction to manage it, is not counted.
